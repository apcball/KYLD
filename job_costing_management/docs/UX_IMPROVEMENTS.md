# Job Costing: การปรับปรุงขั้นตอนใช้งาน

เวอร์ชัน 17.0.1.0.3 — 11 กันยายน 2026

## สิ่งที่เปลี่ยน

- ปุ่มขอวัสดุจากหัว BOQ และแต่ละบรรทัดเปิดหน้าขอวัสดุหน้าเดียวกัน เลือกสินค้าและใส่จำนวนก่อนสร้างใบขอฉบับร่าง
- เปิดจากหัว BOQ จะยังไม่เลือกรายการ; เปิดจากบรรทัดจะเลือกเฉพาะรายการนั้นและเติมจำนวนคงเหลือ
- แสดงจำนวนตาม BOQ ขอแล้ว คงเหลือ และจำนวนที่ต้องการขอ พร้อมยอดประมาณการเฉพาะรายการที่เลือก
- รายการที่ยกเลิกเลือกไม่ถูกนำไปสร้างเอกสาร การยกเลิกหน้าต่างไม่สร้างใบขอ และกดยืนยันซ้ำจะเปิดใบเดิม
- ถ้ายอดคงเหลือเปลี่ยนหลังเปิดหน้าต่าง ระบบอัปเดตยอดให้ตรวจอีกครั้งก่อนสร้างเอกสาร ยังคงอนุญาตให้ขอเกิน BOQ พร้อมคำเตือน
- ตรวจบริษัท โครงการ สถานะ BOQ และเจ้าของหน้าต่างก่อนสร้างใบขอ
- สร้างรายการต้นทุนจาก BOQ ด้วยปุ่มเดิม กดซ้ำเปิดรายการที่มีแล้วโดยไม่เปลี่ยน baseline
- จับคู่ต้นทุนด้วยบรรทัด BOQ และใบต้นทุน ไม่จับคู่จากสินค้าอย่างเดียว หากพบหลายรายการที่เชื่อมกับแหล่งเดียวกันจะแจ้งให้แก้ก่อน
- เมนู Projects เปิดรายการโดยตรง และย้าย BOQ Templates ไป Configuration
- รวมปุ่มคำนวณใหม่เป็น Update Cost Totals โดยคงสูตรเดิมและอัปเดตต้นทุนจริงเฉพาะใบที่อนุมัติหรือเสร็จแล้ว
- ซ่อนคอลัมน์ต้นทุนจริงต่อหน่วยเป็นค่าเริ่มต้น และตั้งชื่อปุ่มแก้ไขแยกเป็น Change Cost Type
- เพิ่มคำแปลไทยสำหรับหน้าต่างและข้อความที่เปลี่ยน

## ความเข้ากันได้

คงโมเดล ฟิลด์ถาวร และ XML IDs เดิม พร้อมชื่อ action เดิมสำหรับการเรียกใช้งาน การเปิดขอวัสดุจากหัวหรือบรรทัด BOQ จะเปิด wizard แทนการสร้างเอกสารทันที

เพิ่ม transient fields สำหรับการเลือกรายการและอ้างอิงใบขอที่สร้างแล้ว ไม่มีการรวม ลบ หรือย้ายข้อมูลต้นทุนย้อนหลัง

เพิ่ม dependency `l10n_th_partner` เนื่องจากข้อมูลผู้รับเหมาเดิมอ้างฟิลด์ `res.partner.branch` และปรับการส่งข้อมูลพนักงาน/แผนกไป RFQ ให้รองรับทั้งกรณีมีและไม่มีโมดูลเสริมที่เพิ่มฟิลด์เหล่านี้

ไม่ได้แก้ไฟล์ข้อมูลผู้รับเหมาที่มีการแก้ค้างก่อนเริ่มงาน และไม่มีงานพัฒนาหรือทดสอบเฉพาะ `buz_dashboard`

## การทดสอบ

ชุดทดสอบมี 22 กรณี: 17 กรณีสำหรับขั้นตอน BOQ/หน้าจอใหม่ และ 5 กรณีเดิมสำหรับการขอวัสดุและ RFQ ใช้ Odoo Form ทดสอบการบันทึกหน้าต่างจริง รวมถึงสิทธิ์ผู้ใช้ทั่วไป/ผู้จัดการ การแยกบริษัท รายการซ้ำ ยอดเปลี่ยน และ view ที่สืบทอดจากโมดูลอื่น

รันทดสอบติดตั้งใหม่ในเครื่อง:

```bash
docker compose -f docker-compose.test.yml up --abort-on-container-exit --exit-code-from odoo
docker compose -f docker-compose.test.yml down
```

Compose ใช้ PostgreSQL 16 และฐาน `MOG_TEST` บน tmpfs โดยไม่เปิดพอร์ตฐานข้อมูลออกสู่ host ข้อมูลทดสอบจะหายเมื่อ container ฐานข้อมูลหยุด

- ติดตั้งใหม่ในเครื่อง: ผ่าน 22 กรณี ไม่มี failure/error
- ตรวจ syntax Python/XML, Compose config และรูปแบบคำแปลไทย: ผ่าน
- อัปเกรดและทดสอบบนสำเนา DEV: ผ่าน 22 กรณี ไม่มี failure/error พร้อมโมดูลที่ติดตั้งอยู่รวมถึง `biz_weekly_budget` และ `buz_auto_analytic`
- Snapshot ก่อน–หลังอัปเกรด: hash ของยอดต้นทุนรายใบ จำนวน BOQ และใบขอ รวมถึงยอดรวมเอกสารตรงกันทั้งหมด

## สถานะการนำขึ้นระบบ

โค้ดทดสอบบน DEV ถูกจัดไว้ในโฟลเดอร์แยกจาก addons ที่ใช้งานอยู่:
`/srv/docker/odoo_kyld/job-costing-ux-test-20260911`

ใช้สำเนาฐาน `KYLD-DEV` และ filestore จาก `odoo_kyld` ใน PostgreSQL/container ชั่วคราวบน Docker network ที่ปิดการเชื่อมต่อภายนอก ไม่รัน cron และไม่อัปเกรดฐานใช้งานจริง

ตรวจเทียบยอดต้นทุนเดิมและจำนวนเอกสารจาก snapshot ก่อน–หลังแล้ว ชุดทดสอบทำความสะอาด container และ network ชั่วคราวเมื่อจบ โดยเก็บ `odoo-test.log`, `before.txt` และ `after.txt` ไว้ในโฟลเดอร์ทดสอบ

ยังไม่ได้ deploy การเปลี่ยนแปลงเข้าสู่ addons ของ `odoo_kyld` หรือ PROD
